The Problem with Desktop Typing

Most software that assists writing on personal computers gets in the way of thought. Built-in operating system autocorrect frequently pops up small, floating bubbles that demand visual confirmation and steal attention. When it misidentifies developer jargon or slang, it replaces terms unexpectedly, forcing you to navigate back, erase the change, and re-type the exact letters while fighting the operating system's suggestion dictionary.

Cloud-based writing assistants present an even worse tradeoff. By sending keystrokes across the internet to remote servers, they introduce hundreds of milliseconds of round-trip latency. More critically, transmitting raw keyboard input off your machine creates an existential privacy hazard. Keystrokes contain passwords, confidential internal emails, proprietary source code, and personal reflections.

We built Inline around a different philosophy: typing assistance should be completely invisible, instantaneous, deterministic, and executed 100% locally in ephemeral memory.

Core Capabilities

Instead of wrapping a browser shell or a heavy background daemon, Inline is compiled as a native, hardened C++20 engine that interfaces directly with low-level macOS subsystem APIs.

Instant Typo Correction on Space: When you complete a word by pressing Space, Inline checks your input against an 82,765 unigram dictionary and 243,342 bigrams in under 40 microseconds using the SymSpell Symmetric Delete algorithm with Damerau-Levenshtein distance ≤ 2. It automatically disambiguates homophones based on preceding context (e.g., distinguishing "there" from "their").

Single-Key Undo: You should never fight your autocorrect. If Inline corrects a word you deliberately intended to type, a single press of Backspace immediately restores your raw keystrokes without cursor drift. The engine notes the rejection and will not re-correct that term in the same context.

Dynamic Run-Together Word Splitting: Fast typists frequently miss the spacebar between words. Inline uses dynamic programming dictionary segmentation to split concatenated phrases into natural words (for example, converting whenI into when I or twowords into two words).

Protected Developer and Chat Jargon: To eliminate accidental corrections during coding or casual messaging, Inline ships with built-in protection for over 180 common developer terms and acronyms (including repo, pr, cli, sdk, api, async, gng, idk, ngl, brb, and tbh).

Absolute Privacy by Design: Inline creates zero network sockets, initiates zero telemetry requests, and writes zero keystrokes to disk. It automatically suspends all tracking inside password fields and PIN inputs (AXSecureTextField) and immediately purges keystroke memory after 30 seconds of inactivity.

How Inline Works Under the Hood

Every keystroke flows through a seven-stage synchronous pipeline designed to execute within microsecond budgets, bypassing locks and heap allocations. Below is how the system processes each key event from the raw hardware interrupt to the screen overlay.

1. Sub-Microsecond Event Interception & Loopback Barrier

Inline hooks into the operating system at the session head using a macOS CGEventTap (specifically kCGSessionEventTap configured with kCGHeadInsertEventTap) listening for kCGEventKeyDown. This tap executes on a dedicated event thread scheduled at real-time QoS.

When Inline injects replacement keystrokes to correct a typo or accept ghost text, those synthesized events would normally be intercepted by our own event tap, causing an infinite loop. To prevent recursion, every synthesized event is tagged with a custom 64-bit integer signature in kCGEventSourceUserData. The hook checks this field first: if the signature matches our private tag, the event bypasses processing in under 2 microseconds. All Enter and Return keys pass through untouched, immediately clearing the buffer. 

// platform/mac/hook/mac_keyboard_hook.mm
CGEventRef eventTapCallback(CGEventTapProxy proxy, CGEventType type, CGEventRef event, void* refcon) {
  int64_t sourceTag = CGEventGetIntegerValueField(event, kCGEventSourceUserData);
  if (sourceTag == INLINE_SYNTHETIC_TAG) {
    return event; // Bypass injected loopback events immediately
  }
  int64_t keyCode = CGEventGetIntegerValueField(event, kCGKeyboardEventKeycode);
  onRawKeyEvent(keyCode, flags);
  return event; // Non-blocking dispatch
}

2. Universal Multi-Tier Caret Localization

Placing ghost text suggestions directly beside your typing requires knowing the exact screen coordinates of the blinking text cursor. In native Cocoa applications, Inline queries the focused UI element's Accessibility attributes via kAXSelectedTextRangeAttribute and converts the character range into screen coordinates using AXUIElementCopyParameterizedAttributeValue with kAXBoundsForRangeParameterizedAttribute.

Web browsers present a unique challenge. In Google Chrome and Electron-based applications, Chromium's internal Accessibility thread updates asynchronously, causing selection ranges to lag behind fast typing bursts. To resolve this, Inline implements a multi-tier fallback ladder using an effectiveLoc probe: when a zero-length selection returns an invalid or outdated bounding box, Inline measures the end-of-text boundary and centers the vertical baseline. This prevents suggestions from floating above search inputs or rendering in microscopic fonts on web search bars like Google, YouTube, and Amazon. Furthermore, horizontal forward monotonicity ensures that suggestions never shift behind your cursor.

3. Dual-Tier Hybrid Predictive Engine

Ghost Writer predictions use a two-layer speculative approach designed to fit within strict memory and latency boundaries without making cloud calls.

Tier 0 (Instant n-gram Trie): A compact in-memory trie indexed from the 243K bigram dictionary evaluates suggestions synchronously on every keystroke in under 1 millisecond. It can complete the active word or propose common two-word continuations immediately.

Tier 1 (Local Neural Transformer): For richer, multi-word contextual completions, an optional out-of-process helper runs an ultra-compact quantized model (such as SmolLM2-135M) over 2 CPU threads via llama.cpp. This model is debounced by 40 milliseconds after the last keypress so it never interrupts rapid typing bursts. Because the KV cache is preserved between consecutive keystrokes, the neural layer updates incrementally in 15 to 30 milliseconds without stressing system memory.

4. Sub-Pixel Ghost Text Overlay & Fluid Type-Through

Predictions render inside a borderless, transparent NSPanel configured with NSWindowCollectionBehaviorCanJoinAllSpaces and setIgnoresMouseEvents:YES. The overlay floats exactly at the caret baseline with sub-pixel precision (±0.5 pt) without taking focus or disrupting the active application.

When ghost text is displayed, Inline handles typing through the suggestion seamlessly. As you type letters that match the predicted continuation, an advanceLayout method shifts the overlay window horizontally to the right in under 0.2 milliseconds without re-querying the predictive model. If you press Tab while a suggestion is visible, the hook swallows the Tab event and injects the remaining characters directly into the host application. If no suggestion is displayed, Tab passes through normally.

5. Deterministic Autocorrect & Single-Key Undo

Autocorrection occurs upon pressing Space or punctuation. The engine runs the SymSpell Symmetric Delete algorithm, which precomputes deletes rather than generating permutations at runtime. Suggestions are filtered by edit distance (≤ 2) and ranked by bigram frequency given the preceding word.

If a correction is applied, the engine records the substitution in an undo state machine. If the user presses Backspace next, the state machine computes the longest common prefix between the raw typo and the corrected text, emits the precise sequence of backspaces needed to erase the difference, and re-types your raw characters. Reverted words are flagged as rejected for that context, eliminating annoying autocorrect loops.

Platform Availability & Windows Beta Notice

Inline is officially supported and production-ready on macOS 12 through 15 (Monterey, Ventura, Sonoma, and Sequoia) on both Apple Silicon (M1, M2, M3, M4) and Intel x86_64 architectures.

Windows Support (Beta): A native Windows port using WH_KEYBOARD_LL for low-level hook interception and SendInput for keystroke injection is currently in beta and is actively being built on the windows-branch. It is undergoing stabilization and is not yet recommended for production typing workflows. If you would like to test the experimental Windows build or contribute to its development, you can inspect the code on the windows-branch on GitHub.
